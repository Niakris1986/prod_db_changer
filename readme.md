# prod_db_changer

## Описание проекта
**prod_db_changer** — утилита для безопасной синхронизации изменений из тестовой базы данных в продуктивную PostgreSQL-БД без потери или порчи существующих данных.

## Основная идея и уникальность
- **Идея**: автоматизировать перенос обновлений схемы (DDL) и справочных данных (reference tables) из тестовой среды в продуктивную, сохраняя все существующие записи и не затрагивая уже работающие таблицы и поля.
- **Уникальность**:  
  - Динамическая генерация DDL по структуре тестовой БД  
  - Пошаговая проверка и добавление только **отсутствующих** таблиц и колонок  
  - «Умная» синхронизация справочных таблиц с вычислением списка на вставку и на обновление  
  - Механизм «кастомных миграций» для любых других таблиц  
- **Целевая аудитория**:  
  - DBA и DevOps-инженеры, ответственные за CI/CD продакшн-баз  
  - Backend-разработчики, работающие с PostgreSQL и желающие автоматизировать миграции  

## Особенности реализации и дальнейшие шаги
1. **Синхронизация схемы**  
   - Сравниваем списки таблиц в `information_schema.tables`  
   - Генерируем `CREATE TABLE ...` только для отсутствующих таблиц  
   - Для общих таблиц сравниваем колонки и при необходимости `ALTER TABLE ADD COLUMN` или `ALTER TABLE ALTER COLUMN TYPE`  
2. **Синхронизация справочных таблиц**  
   - Загружаем все записи из тестовой и из продовой таблиц  
   - Вычисляем, какие записи вставить, а какие — обновить  
3. **Кастомные миграции**  
   - Пример для таблицы `orders` показывает, как можно дописать логику частичной или условной миграции данных  
4. **Логирование**  
   - Используется стандартный модуль `logging` с выводом на уровень INFO/DEBUG  
5. **Дальнейшее развитие**  
   - Поддержка сложных типов колонок (JSONB, ARRAY, ENUM)  
   - Учёт nullable и дефолтных значений при сравнении  
   - Пакетная миграция больших справочных таблиц с разбиением на чанки  
   - Поддержка произвольных схем (не только `public`)  

## Требуемые зависимости и ресурсы
- **Python ≥ 3.6**  
- Пакеты из `requirements.txt`:
  - `psycopg2` — драйвер PostgreSQL  
  - `unittest` (входит в стандартную библиотеку)  
  - `logging` (стандартный модуль)  
- **Доступ к тестовой и продуктивной PostgreSQL-БД**  
  - Необходимы параметры подключения (host, port, dbname, user, password)

## Технические особенности
- **Инспекция схемы** через `information_schema.tables` и `information_schema.columns`  
- **Генерация DDL** вручную в методе `_get_create_table_ddl` или опционально через `pg_dump --schema-only`  
- **Синхронный режим**: методы открывают два соединения одновременно (`with connect(...) as conn`)  
- **Расчёт diff-ов данных**: `calculate_inserts` и `calculate_updates` работают по полю `id`  
- **Возможность расширения**:
  - Добавить поддержку других ключей (не только `id`)  
  - Средства отката (rollback) при ошибках  
  - Конфигурацию через файл YAML/JSON
